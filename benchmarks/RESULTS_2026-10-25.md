# Full-call decision benchmark — 2026-10-25

**Development-only evidence.** Run on the owner's Windows PC against the
14 synthetic, hand-labeled call scenarios in `benchmarks/call_states_dev.json`.
No live phone calls were placed. These cases are too small and too tailored
to determine production accuracy. Do not market these numbers as real-world
accuracy, and do not assume the apparent CPU-rule advantage will generalize.

## Backends actually evaluated

- **TypeSafe Jev 1.14.0**, live authenticated System One requests using an
  existing Windows-user DPAPI vault. All **14/14** benchmark requests
  succeeded with **zero transport or parsing failures**.
- **PhoneDex CPU rules**, local Python regex/pattern classifier.
- **Kev-4B / Kev-0.8B: NOT RUN.** No Kev executable was found on PATH; the
  common local endpoints tested did not respond. This does not prove Kev
  cannot be installed or is absent from every environment.

The TypeSafe key was never printed, stored in the report, or copied into a
new `.env`. One separate preliminary TypeSafe smoke request succeeded before
the 14 benchmark calls.

## Results

| Decision | Jev correct | Jev wrong | Jev abstain | Rules correct | Rules wrong |
| --- | ---: | ---: | ---: | ---: | ---: |
| Current call state | 11 | 3 | 0 | 12 | 2 |
| Task completed | 12 | 1 | 1 | 13 | 1 |
| Human handoff requested | 13 | 1 | 0 | 14 | 0 |
| Retry needed | 7 | 0 | 7 | 12 | 2 |
| Unanswered questions | 4 | 4 | 6 | 13 | 1 |

All columns use the same **14** synthetic scenarios per decision type.
The threshold for a Jev yes/no decision was **0.72**; uncertain probabilities
were counted as abstentions, not silently marked correct. Rules emit hard
classifications with no calibrated confidence.

| Latency | TypeSafe Jev (remote) | CPU rules (local) |
| --- | ---: | ---: |
| Median | 256.360 ms | 0.009 ms |
| Reported p95 (14-case sample) | 319.969 ms | 0.013 ms |
| Maximum | 496.904 ms | 0.027 ms |

The 14 Jev benchmark requests took approximately **3.604 seconds** overall.
The CPU figures reflect execution of simple patterns only; Jev figures include
hosted model computation and network overhead. These are not fair compute-only
comparisons, nor a measurement of simultaneous live call capacity.

## Observed problems to address

- Jev abstained on **7/14** retry decisions and **6/14** unanswered-question
  decisions. Unanswered-question detection needs a better task representation
  and separately tracked requested facts.
- Jev treated the synthetic **"press star for a representative" automated
  menu** as a human handoff request. This is a **false-positive transfer
  hazard** and reinforces keeping the observer advisory-only.
- The CPU rules misclassified discussion **about voicemail services** as
  actual voicemail and failed to recognize an automated **"press star"** menu.
- Many fixtures have unanswered questions by construction. This inflates
  baseline scores for rules that default to "still unanswered."
- Confidence calibration, long-call behavior, token costs, GPU usage, and
  stream-by-stream accuracy were not assessed by these 14 examples.

## Next checks
